Adinn Design Task Manager - Decline / Split / Swap Enhancement
Date: 2026-08-08

Approval rule
-------------
Either Designer Head OR Admin can approve/reject a Designer request.
The first valid decision finalizes the request. A second approval/rejection is blocked.

Enhancements included
---------------------
1. Designer request creation remains status-specific:
   - Review & Analysis: Decline, Split, Swap
   - Need Clarification: Decline, Split, Swap
   - Yet to Start: Split, Swap
   - In Progress: Split, Swap
2. Duplicate pending requests of the same type are blocked for the same task.
3. Swap target must be an active Designer and cannot be the current Designer.
4. Split count must be >= 1 and must leave at least one creative on the original task.
5. Approved Split creates a child task and reduces the original task creative count.
6. Approved Swap changes the assigned Designer.
7. Approved Decline is recorded but does not delete/change task status or automatically unassign it, because designer_id is currently non-null in the schema.
8. Admin can approve/reject requests from Admin Dashboard.
9. Designer Head can approve/reject requests from Designer Head Dashboard.
10. Request creation/approval/rejection is recorded in Pipeline History.
11. Request detail UI shows approver, target designer, split details and request attachments.
12. Pending request tags replace duplicate action buttons on Designer task detail.
13. Row locks are used during decisions to prevent double execution when Admin and Designer Head act at nearly the same time.
